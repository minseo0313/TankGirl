# OV5647 카메라 미인식: config.txt 변경으로 해결

작성일: 2026-11-06  
상태: **센서 인식 및 실제 사진 촬영 성공 확인**

## 증상

리본 케이블로 연결한 5MP OV5647 IR-CUT 카메라를 `gi.py`에서 열지 못했다. IR-CUT과 적외선 조명은 주야간 촬영 기능이며, 카메라 연결 방식은 CSI다. 케이블의 `AWM 20624`는 케이블 규격 표시로 센서 모델명이 아니다.

```text
VIDEOIO(V4L2:/dev/video0): can't open camera by index
```

실제 검사에서도 센서가 인식되지 않았다.

```bash
vcgencmd get_camera
libcamera-hello --list-cameras
python3 -c "from picamera2 import Picamera2; print(Picamera2.global_camera_info())"
```

```text
supported=1 detected=0, libcamera interfaces=0
No cameras available!
[]
```

`/dev/video0`도 없었다. `/dev/video10` 등은 코덱·영상 처리 장치일 수 있으므로 카메라 번호를 임의로 10으로 바꾸는 해결책은 쓰지 않았다.

## 핵심 변경: /boot/config.txt

**카메라를 교체한 것이 아니라, 같은 OV5647을 다루는 OS 설정을 변경했다.**

변경 전에는 구형 카메라 방식을 켜는 `start_x=1`이 있었다. `bcm2835_v4l2` 모듈은 올라와 있었지만 카메라는 감지되지 않았다. libcamera/Picamera2에서도 카메라 목록이 비어 있었다.

변경 전의 핵심 설정:

```ini
start_x=1
```

변경 후에는 이 줄을 주석 처리하고, 파일 맨 아래 `[all]` 구간에 OV5647을 명시했다.

```ini
#start_x=1

# 아래 설정은 파일 맨 아래 기존 [all] 구간에 추가
[all]
camera_auto_detect=0
dtoverlay=ov5647
```

위 예시는 카메라 관련 부분만 발췌했다. 기존 HDMI·GPU·FKMS 설정을 삭제하거나 위 내용으로 파일 전체를 교체하지 않는다. `[all]`도 이미 있다면 해당 구간에 두 줄만 추가한다.

| 변경 | 하는 일 | 변경 이유 |
| --- | --- | --- |
| `start_x=1` → `#start_x=1` | 구형 카메라 방식 활성화 설정을 해제 | libcamera 방식으로 카메라를 사용하기 위해 |
| `camera_auto_detect=0` | 카메라 모델 자동 감지 비활성화 | 모델을 알고 있으므로 직접 지정하기 위해 |
| `dtoverlay=ov5647` | OV5647용 장치 트리 오버레이 로드 | 커널에 센서 연결 정보를 제공해 초기화하도록 하기 위해 |

핵심은 **“카메라 모델을 알아서 찾게 두는 대신 OV5647임을 OS에 직접 알려준다”**는 것이다. Picamera2 패키지 설치만으로 센서가 감지된 것은 아니다. 이때 Picamera2는 이미 설치돼 있었다.

## 적용 명령

라즈베리파이 SSH 터미널에서 백업 후 편집한다.

```bash
sudo cp -n /boot/config.txt /boot/config.txt.before-camera
sudo nano /boot/config.txt
```

`-n`은 기존 백업을 덮어쓰지 않는다. 백업이 이미 있으면 이번 편집 직전 상태와 다를 수 있다.

위 카메라 설정을 반영하고 **Ctrl+O → Enter → Ctrl+X**로 저장·종료한 뒤 재부팅한다.

```bash
sudo reboot
```

이 작업은 구형 Raspberry Pi OS Bullseye 계열의 이번 환경 기준이다. 다른 OS의 설정 경로·카메라 방식을 그대로 가정하지 않는다.

## 변경 후 검증

### 센서 인식 성공

```bash
libcamera-hello --list-cameras
```

실제 출력 발췌:

```text
Available cameras
-----------------
0 : ov5647 [2592x1944] (/base/soc/i2c0mux/i2c@1/ov5647@36)
```

**판단:** 같은 OV5647 센서가 새 설정에서 정상적으로 검색됐다.

### 실제 촬영 성공

```bash
libcamera-still -n -t 2000 -o /home/pi/camera-test.jpg
```

`-n`은 미리보기 없이 실행, `-t 2000`은 촬영 전 약 2초 대기, `-o`는 저장 경로다.

실제 출력 발췌:

```text
Registered camera /base/soc/i2c0mux/i2c@1/ov5647@36 to Unicam device /dev/media3 and ISP device /dev/media0
Still capture image received
```

**판단:** 목록에만 나타난 것이 아니라 실제 이미지 획득도 성공했다. 구형 `raspistill` 명령은 설치돼 있지 않았으며, 그 사실 자체는 카메라 고장 증거가 아니었다.

## 왜 이후 Python 코드도 바꿨나?

원래 `gi.py`는 OpenCV의 구형 V4L2 카메라 경로를 사용했다.

```python
cam = cv.VideoCapture(0, cv.CAP_V4L)
ret, frame = cam.read()
```

OS에서 libcamera 촬영은 성공했지만, 이 기존 코드에서는 `frame=None`이 나와 영상을 자르는 줄에서 오류가 발생했다.

```text
TypeError: 'NoneType' object is not subscriptable
```

따라서 촬영에 성공한 카메라 시스템을 Python에서도 사용하도록 **입력 부분을 Picamera2로 변경**했다. OpenCV는 영상 처리·표시·저장에 계속 사용한다.

```text
OV5647 → libcamera → Picamera2로 프레임 획득 → OpenCV로 처리·표시
```

현재 입력 설정은 640×480, `RGB888`이며 Picamera2의 이 형식은 OpenCV에 맞는 BGR 바이트 순서로 반환된다. 종료·예외 시 카메라와 모터를 정리하는 처리도 함께 추가했다.

## 확인 범위와 남은 제한

- 설정 변경 후 OV5647 인식, 사진 촬영, 이후 프로그램 화면의 영상 출력은 확인됐다.
- 처음부터 동일한 OV5647 센서를 사용했다. 다른 모델로 바꾼 작업이 아니다.
- **구형 방식에서 처음 감지되지 않았던 정확한 이유는 미확정**이다. 설정 변경과 재부팅을 함께 수행했으므로 특정 한 줄만이 유일한 원인이었다고 단정하지 않는다.
- 적외선 조명·IR-CUT 자동 전환의 주야간 성능은 별도로 검사하지 않았다.
- GPIO 적외선 리모컨용 `gpio-ir` 설정은 이 CSI 카메라 인식 설정과 관계없다.
