# gi.py 전체 화면의 흰 여백 해결

작성일: 2026-11-06  
상태: **전체 화면 표시 해결 — 사용자 확인**

## 증상

OV5647 카메라 영상과 조작 메뉴는 나오지만, 화면이 왼쪽 위에만 표시되고 오른쪽·아래에 넓은 흰 여백이 남았다. VNC 창을 크게 해도 프로그램 내용이 화면을 채우지 못했다.

이번 이슈는 **카메라 인식이나 촬영 실패가 아니라 화면 표시 크기 문제**다.

## 원인과 판단 근거

프로그램이 그리는 화면 `viewWin`은 **800×480**으로 고정돼 있다. 그 안에 카메라 영상 **640×480**과 좌우 메뉴가 배치된다.

```text
원본 조작 화면: 800 × 480
┌─────────┬────────────────┬─────────┐
│ 왼쪽 메뉴 │ 카메라 640×480 │ 오른쪽 메뉴 │
│   80px   │                │   80px   │
└─────────┴────────────────┴─────────┘
```

기존 표시 코드는 이 고정 크기 배열을 그대로 창에 전달했다.

```python
cv.imshow('Out', viewWin)
```

VNC 데스크톱은 이 배열보다 컸다. 전체 화면 창을 요청하더라도 **화면 배열 자체가 데스크톱 크기로 늘어나는 것은 아니었다.** 사용자 사진에서도 원래 조작 화면은 왼쪽 위에 있고 나머지가 여백으로 보였다.

먼저 OpenCV의 `WINDOW_NORMAL`, `WINDOW_FREERATIO`, 화면 비율 속성을 이용한 자동 확대를 시도했다. 중복 `namedWindow` 호출도 제거했지만, 사용자 사진에서 여백이 계속 확인됐다. 따라서 이 환경에서는 해당 설정만으로 해결되지 않았다고 판단했다. 정확한 OpenCV GUI 백엔드의 동작 원인은 별도로 규명하지 않았다. 중복 창 호출이 원인이었다고 확정한 것도 아니다.

## 해결: 표시할 때만 직접 확대

변경 파일: [aicar/gi.py](../../aicar/gi.py)

### 1. 현재 VNC 데스크톱 해상도 확인

라즈베리파이의 X 데스크톱 정보를 `xrandr --current`로 읽고 현재 화면의 가로·세로 크기를 추출한다.

```python
import re
import subprocess

display_info = subprocess.check_output(['xrandr', '--current'], text=True)
display_match = re.search(r'current\s+(\d+)\s+x\s+(\d+)', display_info)
if display_match is None:
    raise RuntimeError('xrandr에서 현재 화면 해상도를 확인하지 못했습니다.')
DISPLAY_X, DISPLAY_Y = map(int, display_match.groups())
if DISPLAY_X <= 0 or DISPLAY_Y <= 0:
    raise RuntimeError('화면 해상도는 양수여야 합니다.')
```

해상도를 코드에 1280×720 등으로 고정하지 않고 실행 당시 데스크톱 크기를 사용한다. `xrandr`를 실행하지 못하면 예외로 종료되며, 기본 크기로 자동 복구하는 처리는 없다.

### 2. 화면에 보여주는 배열만 확대

변경 전:

```python
cv.imshow('Out', viewWin)
```

변경 후:

```python
cv.imshow('Out', cv.resize(viewWin, (DISPLAY_X, DISPLAY_Y)))
```

카메라와 메뉴가 합쳐진 **800×480 화면 전체**를 데스크톱 크기로 확대해서 전달한다. `viewWin` 원본은 변경하지 않는다.

따라서 카메라 입력은 여전히 **640×480**이고, 기존 영상 처리·촬영 데이터 크기·메뉴 배치는 그대로다. 화면을 크게 보이게 하는 변경이지 카메라 촬영 해상도를 높이는 변경이 아니다.

### 3. 확대된 화면의 마우스 좌표를 원래 크기로 환산

화면만 확대하면 마우스 위치와 기존 조향 계산의 좌표가 달라진다. 기존 제어는 800×480 기준이므로, 콜백에서 받은 확대 영상 좌표를 다시 환산한다.

```python
mouseX = min(799, max(0, x * 800 // DISPLAY_X))
mouseY = min(479, max(0, y * 480 // DISPLAY_Y))
```

예를 들어 표시 크기가 1280×720이면 다음과 같다.

| 화면에서 가리킨 위치 | 기존 제어에 전달되는 위치 |
| --- | --- |
| 왼쪽 위 `(0, 0)` | `(0, 0)` |
| 중앙 `(640, 360)` | `(400, 240)` |
| 오른쪽 아래 `(1279, 719)` | `(799, 479)` |

`min`과 `max`는 좌표가 원본 범위인 가로 0~799, 세로 0~479를 벗어나지 않도록 제한한다. 우클릭 정지 등 기존 버튼 동작은 유지했다.

## 적용 방법

프로그램을 종료하고 **PC Windows PowerShell**에서 수정 파일을 전송한다. IP가 바뀌면 현재 주소로 변경한다.

```bash
scp "C:\AutoTank\aicar\gi.py" "C:\AutoTank\aicar\check_display.py" pi@<Pi IP>:/home/pi/aicar/
```

**라즈베리파이 VNC 데스크톱의 터미널**에서 실행한다.

```bash
cd ~/aicar
python3 check_display.py
sudo python3 gi.py
```

`check_display.py`는 모터와 카메라를 초기화하지 않고, `gi.py`의 실제 마우스 콜백을 추출해 실행한다. 800×480, 1280×720, 1024×768에서 중앙·모서리·범위 밖 좌표의 환산을 검사한다.

## 확인 결과와 남은 제한

- **전체 화면 표시 성공:** 적용 후 사용자가 “오 전체 화면으로 됐다”라고 확인했다.
- **좌표 검사 실행 결과:** 검사 파일은 추가했지만 PC 실행 도구 오류로 직접 실행하지 못했고, 라즈베리파이 검사 출력도 아직 전달받지 않았다.
- **실제 마우스 조향:** 위치 일치와 차량 동작은 별도 확인이 필요하다. 바퀴를 띄운 상태에서 먼저 확인한다.
- **화면 비율:** 여백 없이 가득 채우므로 데스크톱과 원본 화면 비율이 다르면 영상과 글자가 가로 또는 세로로 늘어날 수 있다.
- **해상도 변경:** 실행 시 한 번 해상도를 읽는다. 실행 중 VNC 해상도를 바꾸면 프로그램을 다시 시작한다.
- **환경:** 현재 X11/FKMS·VNC 환경을 기준으로 했다. `xrandr`가 필요하며 여러 모니터 환경에서는 개별 모니터가 아닌 전체 데스크톱 크기를 읽는다.
